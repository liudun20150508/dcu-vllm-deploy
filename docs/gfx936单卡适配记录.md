## 〇、一句话结论

这台卡是 **gfx936（不是 906/928）**。之前 906 上最难的几个补丁（triton arch-spoof、FORCE_AITER、FORCE_FP8、glibc-shim）**在这里大多不需要**；gfx936 本身在 vllm_hcu 的 `on_gfx93x()` 白名单内。真正的坑是环境重建 + 几个 gfx936 专属的小坑，全部定位并修复。

## 二、踩坑与修复（gfx936 专属，按发现顺序）

1. **venv 没 python3.10 头文件** → triton 编译 `hip_utils.c` 缺 `Python.h`。系统 python3.10 是 `python3.10-minimal`，apt 无 `python3.10-dev`。→ 从清华 jammy 源下载 `libpython3.10-dev` deb 手动 `dpkg -i`。
2. **vllm_hcu 源码补丁没生效**（`set_deepep_auto_use_low_latency` ImportError）→ `--no-deps` 装 wheel 不触发 post-install hook。→ 手动 `python -m vllm_hcu.post_install`（软链 modular_kernel + 应用 `patches/` 全部源码补丁）。
3. **sitecustomize 的 `_Finder` 被 virtualenv 干扰**（Duplicate op name）→ `sys.meta_path` 里已有 `_virtualenv._Finder`，sitecustomize 按 `type(f).__name__ == "_Finder"` 误判自己已装而跳过。→ 改为 `type(f) is _Finder`（`dupfix/sitecustomize.py`）。
4. **tilelang 误判 CUDA target**（`Cannot find target.build.tilelang_cuda`）→ 机器有 `CUDA_HOME=/usr/local/cuda` 残留，`determine_target("auto")` 先查 cuda 就返回 True。→ 启动时 `unset CUDA_HOME CUDA_PATH`（HIP 版 `target.build.tilelang_hip` 存在）。
5. **aiter fused_moe 签名不匹配**（`unexpected keyword argument 'num_local_tokens'`）→ vllm 260611 的 `_aiter_ops.py` 传了 `num_local_tokens/dtype/hidden_pad/…`，海光 aiter 260813 没有。→ `das185_patch.py` 补丁4 给 `aiter/fused_moe.py` 加这些 kwarg（单卡 EP=1 下为 None/0，忽略）。
6. **gfx936 的 MXFP4 门槛**（j42 同款）→ `rocm_aiter_moe.py` 的 `_supports_quant_scheme` 只认 `on_gfx950()`。→ `das185_patch.py` 补丁3 改成 `on_gfx950() or gfx936/gfx938`。
7. **dummy 缩小模型后 KV cache 反量化 OOM** → 模型权重只剩 ~2GB，vllm 按 util 0.9 把剩余 ~53GB 全给 KV cache（146 万 block），decode fallback 反量化整个 cache 要 91GB。→ `gpu_memory_utilization=0.15` 限制 KV cache 预算（真实 48GB 权重场景不会触发）。
